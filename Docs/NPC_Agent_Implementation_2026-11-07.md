# NPC agent：知识权限与实际对话接入

本批执行用户批准的优化方案。九份已审委托的目标、用途、内部底稿和结算揭示保持原文；人设故事、图鉴、合成评分、每日推进与地图不改。

## 实际调用链

游戏的ForestNPCDialogueSubsystem读取当日委托、人物层级、真实历史与前回合记忆 → 同一接口的语义分析 → 本地核对计划、权限、原话证据及保存结果 → 结构化台词 → 明确配方结构检查 → 语义复核 → 最多一次针对性内容修复 → 只显示最终采用台词、登记它实际讲出的事实。

分析、生成和复核各有独立规则。历史台词是引用数据，复核请求移除台词生成的格式要求，避免协议串扰。真正网络失败不显示未经复核的草稿。

## 知识与逐层披露

- 已审底稿拆成来源可核对的事实；数字依据段、目标与结算揭示不传给NPC对话模型。
- 元素性质按本地目标引用玩家图鉴的同源句子，只传性质文本，不传档位索引。
- 图鉴effect事实必须同时选入同元素的当前委托用途对象（task.<element>.a），或者该对象已经实际讲过。此约束由生产原生策略校验，防止把局部用水误读成成品受潮、只讲抽象强弱却漏用途。
- 允许讲、计划选择、实际讲出是三个集合。每轮最多两条新的任务事实；已讲事实可承接。约束不充作已讲事实，人物事实按当前层级开放，深层委托动机受第三层限制。
- 新人物事实表取自现有AlchemyPersonaProfiles.inl，不创造人物与情节。第二层可从真实追问当前用途缘由或类似工作经历自然进入，不要求玩家猜旧职业关键词；第三层才要求相关深层追问。引用、否定、转述、物品标签和要求绕过熟悉度不授权升级。
- 计划非法、超预算或缺用途配对时，把具体校验反馈和上次输出交给分析器重试一次；失败不假造计划。测试保留每次分析结果，便于查清漏选和漏讲。

## 数值、流程与记忆

本地检查仅拦明确配方结构；普通数量、出版三本书、拒绝替玩家判断数字不再被宽泛禁词误杀。猜数确认、比例/编码、任务矛盾、虚构回忆与越层由当前上下文语义复核处理。强度描述不得被改写成另一档，也不得冒充当前实际天气或场景变化。

接取根据真实NPC委托和最新玩家自愿承担的证据识别，本地核对角色、顺序、原文与当前任务后保存。展示不接取、不交付、不结算。保存结果和台词结果分开；失败保留玩家原话和已保存动作收据，不重复执行接取。流程兜底明确回小屋合成台调配、封瓶，不当面交原料。

保留Set/Get/ClearRoundMemoryContext与既有紧凑账本读取；旧记忆是资料，不能覆盖当前状态与权限。普通数量和布尔值保留，目标、配方、评分和层级字段排除。不增加记忆衰减、信任、关系效果或新触发规则。

每轮共享45秒期限、最多6次网络请求，格式重试和内容修复共享预算。退出取消请求；NPC、日期、回合或知识指纹变化后旧回调不能提交。

## 应用与迁移

同路径合并本批配置、插件头源、游戏对话头源和Build.cs，重编译、正常重启。新ForestPersonaFacts.json随NonUFS分发；沿用现有网关与模型配置，无密钥、地图资源和编译产物上传。

知识修订3重建旧粗主题披露账本；保留熟悉度、已接任务、收据及有效历史。修订1旧会话沿用已有归档规则。配置指纹变化重建事实编号、拒绝过期回调。不直接修改用户存档，不重算旧收据；应用前按原流程备份存档。

## 证据边界

有限样本、同接口模型的不同评审规则及盲读估计不等于独立人工验证，也不能保证所有自由对话永远正确。请求沿用deepseek-chat；实际返回模型名见报告（本轮为deepseek-flash）。

未运行UE/PIE：真实SaveGame、UI、反射装载、运行时取消、Windows和打包未验证。便携桥直接读取生产策略与接取校验头，但UE容器/正则兼容、JSON读取、HTTP调度及保存结果仍由宿主适配，不能代替引擎实测。
