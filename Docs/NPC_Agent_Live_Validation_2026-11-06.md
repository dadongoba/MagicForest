# NPC线上对话检查与修正

## 范围

用户提供凭据后，使用现有DeepSeek兼容网关和deepseek-chat实际调用模型。密钥仅在测试进程环境中使用，没有写入工程、测试报告或Git。测试宿主编译生产人物工厂、熟悉度触发、BuildPersonaSystemPrompt、数字检查与主题限额；JSON装载、会话保存、接取状态和HTTP调度由宿主代替UE，因此不是PIE实机验收。

完整一组包括九份委托各七轮、三位人物各五轮、称呼记忆读取和记忆不能自行解锁秘密，共80轮。逐项询问用途、火、风、水、强弱边界、玩家猜数、当面交原料；人物检查包括未解锁时逼问、自然线索、深层线索和后续承接。

## 发现的问题及处理

1. 测试宿主最初使用系统宽字符格式化时丢失中文人设前缀。该组结果作废，不能用来判断游戏运行时。改为确定性的占位格式化，检查三个名字、三层完整文本及基础人设/日常状态确实存在，再发起线上测试。
2. 主题计划偶尔漏掉topics字段，旧代码默认用途后继续生成，造成模型猜补元素作用。现在要求topics优先、完整字段、短证据摘录，额度从300增至600；原生检查数组、最多两个主题和合法名称，格式不合格重试一次，仍不合格则返回knowledge_plan_invalid，不用猜测回答、不登记任务。
3. 复核只看局部线索时，难以核对错误猜补。现两个对话入口都给复核器额外提供完整的无数字任务事实，仅核验真假；台词模型仍只看到本轮开放及此前开放的主题。完整核验资料不构成披露许可，也不进入玩家台词。
4. “一开炉”“一受热”“两回事”“清一清”等普通表达被数字检查误拦，重复重写后进入兜底。补充有限的常用表达豁免，同时回归阿拉伯/全角/中文/英文/编码数字及猜数确认的拦截。
5. 人物层级允许讲述的事实偶尔被误当成已经讲过的事实。生成和复核均明确：人物底稿不是发言记录，声称已经讲过须有实际历史或明确前回合记忆支持；首次讲述直接说明。
6. 模糊询问“这份材料用来做什么”应承接当前委托，不凭空要求拿出原料。连续重写仍失败时优先使用当前委托的已审核用途作为安全回复，并再过猜数检查；只有用途也不安全时才用原角色通用兜底。这不会开放新的强度或秘密。

## 结果与样本

全量80轮完成，自动检查通过，期间发生6次保守兜底；人工复核继续发现普通措辞误拦与首次讲述被当成已讲述的问题，因此不能只凭PASS就称体验完整。随后修正并做定向复测，分组次数和结果见本批CHANGELOG及测试记录。各组不是同一版源码的一次连续全量测试；不能将早期“缺少凭据”记录或作废宿主结果当成当前线上结论。

已观察到的有效输出示例：

- 铁匠第三天的火：“连接处得烧红，红到能锻接的程度，但不能把整件熔成液体。”水：“小件得能整个泡进去，朝里朝外都浸到，褶皱里干结的旧污才泡得松、洗得出来。”
- 接线员第二天的水：“只在封口胶表面薄薄附着，不滴落，还得保持柔韧；里面的药粉仍然干燥。”不再把这件事说成额外加水给药粉。
- 玩家猜数字时：“不猜数。火候是烧红能锻接、别熔成液体；风要持续送气；水先清洗，不倒进炉里。”没有肯定或否定玩家猜中的具体数字。
- 接线员深层：“有些记录是我交上去的。后来有人被带走，我知道。那天晚上我还睡得很好。”同一组未解锁时拒绝完整讲出往事。
- 小说家深层说到书被禁、作者身份不当、当夜离开且没带样书；未解锁时不提前确认这些事实。
- 传入玩家称呼“青苔”后，能正确读出；传入要求忽略层级的伪记忆，没有因此开放秘密。

## 边界

这是有限场景的模型回归，不保证任意提示攻击或所有自然语言都正确。普通表达仍可能被保守拦截而退回用途，导致这一轮的具体线索不完整，需要继续追问；语义复核与说话模型共用接口，会增加请求数和等待时间。原生策略、编译、远端回复、游戏内运行是不同验证层次；没有打开UE、PIE、实测存档或打包，也没有把密钥安装成长期游戏配置。
