# 三位NPC人设运行时接入

## 这次实际改变的入口

`AlchemyGameplaySubsystem.cpp` 直接包含新增 `AlchemyPersonaProfiles.inl`，三个人设工厂从该文件构建基础语气、日常状态、秘密背景、三层提示、例句和解锁线索。不是把Markdown路径写进记录。

主模块 `RegisterForestPersonas` 仍把blacksmith/operator/novelist映射为natta/fawnia/forest_witch；真实对话的 `RequestNpcReply` 使用 `BuildPersonaSystemPrompt`，因此下一次正常启动已编译的工程后，会生成包含新版人物定义的请求。共享插件的原有请求入口也读取相同工厂。

- 小说家：初见浪漫、亲近、轻浮多情，愿意调笑和联想；认真问任务时收回跑题；深层交代三本书、身份针对、禁书与无样书出逃，保留性向，严肃片刻不永久丢掉个性。
- 铁匠：急性子、脾气不好，不愿泛评人事；具体问题认真解释。背景改为曾真心参与清理人们住处，有人后来被带走；撤去具体老师、旧伤视觉和被迫无辜技术员解释。第三层线索对应人们住处、清理运动和实际参与，不再依赖老师。
- 接线员：活泼、话多、健忘，路线能力保留；不再强制每次改词，不用健忘推翻真实进度或核心经历。背景使用有人、人们，撤去具体同事；第三层说清标记与安睡，不要求永久少话。

小说家第二层可以承认三本书，因此“看到三本书就自动解锁第三层”的旧直接触发移除，仍可凭禁书、身份针对等具体线索进入深层。熟悉度单调规则与实际解锁算法保留。

## 回复、记忆与旧存档

新增 `AlchemyPersonaPolicy` 在真实回复进入显示和正式历史前清理括号、方括号和星号中的表演说明。清理后为空时，使用当前角色的自然兜底，替代单字敷衍或固定索要元素；网络请求失败仍走错误状态，不伪装成成功。普通语言数量不由这一步删除。

首次与某角色开始新版对话时，根据PersonaRevision把旧版短期历史保存在ArchivedPersonaHistory，不再拿旧台词作模仿范例；迁移保存失败撤回本次变动。已有熟悉度、秘密旗标、任务接取和结算记录不重置，长期记忆文件也不删除。

旧紧凑记忆中的老师/具体同事绑定在重建上下文时被过滤；共享世界记忆同样过滤，避免经另一角色绕回来。原始旧账本保留，不做破坏性清理。这是按已知旧词和旧稳定键进行的保守过滤，可能同时省略带这些词的无关旧摘要，不宣称能识别全部语义变体。

总结请求附带当前人设与实际熟悉度层的披露范围。待总结旧会话里的退役背景发言不送入总结；新补丁进入原有校验器前再次过滤退役背景，避免重新写回。摘要提示资源移除teacher例子，并加入稳定个性与健忘边界。离线模拟也使用各角色不同口吻，但仍明确是模拟，不宣称其为在线生成。

## 同步清除的委托文字冲突

铁匠旧第三日文案直接声称手部肿胀，和用户要求及新角色输入冲突，因此仅把Wish、OpeningLine和SensoryPrompt改为炉边积热与气流需要退去。没有给角色增加伤势或新动作。

九份委托的Target、SlotCount、CostLimit和MustCards均与基线一致。此批没有完成此前待定的全正值、第三天三元素、新任务底稿/数值及图鉴统一；原目标字段仍在对话输入中，不能把本次人设接入宣称为数字泄露防护完成。

## 本次验证与限制

- 用户当前Air完整工程Mac UE5.8 arm64编译链接通过：第一轮18.91秒，后续6.06秒，最终含共享世界记忆过滤与离线口吻的构建9.16秒。
- `run_persona_policy_tests.py` 提取生产人物工厂、GetPersonaProfile、实际层级触发函数、旧背景过滤和回复清理，用小型STL适配编译执行。验证三角色身份、三层、核心性格与背景，场景别名，旧背景命中与有效进度不被过滤，括号清理、兜底、普通数量保留，第二/三层触发与不倒退。
- 静态逐项对照九份目标、槽位、额度与指定材料，确认未改；实际角色注册到请求再到回复处理的调用路径已核对。
- 没有启动、打开或重启UE，没有调用在线模型。真实对话自然程度、真实存档迁移、异步异常、JSON补丁运行合并、PIE、Windows和打包仍需后续验收；便携测试不替代这些验收。

## 应用

合并主模块ForestNPCDialogueSubsystem.h/.cpp，插件AlchemyGameplaySubsystem.cpp、新增AlchemyPersonaProfiles.inl和AlchemyPersonaPolicy.h/.cpp，以及Resources/DialogueMemorySummarizerPrompt.md，正常重新编译后重启工程。新增源码必须一并同步，单独复制旧CPP无法包含新工厂。

无需新模型、外部服务、地图、美术、配置或新的API key。建议先备份Saved/SaveGames；本次开发未修改用户正在使用的存档。若编辑器当前已打开，其内存中的旧原生模块不会仅因本次编译自动替换，需正常重启后加载新模块。
