## 每日数值

当前 Dreamscape 区域采集器不再统一发3点材料。共享 DailyMushroomSubsystem 从 Config/ForestDailyResourceValues.json 读取火/风/水三条规则，含规则ID、来源ID、固定元素、最小/最大点数、种子盐和标签；本批范围均为1–9，可继续扩展字段。

生成结构化 FDailyMushroomCardRow 时，由日期、稳定资源ID、元素和种子盐初始化独立 FRandomStream。采集点生成时记录当天数值，提示显示这一值，完成采集时再核对同一日表行并写入背包。不会消费位置生成随机流，不修改原资源位置、数量、收集ID或再生账本。同节点同一天重载可复现，跨日重新取值，允许随机结果偶然重复。

火/风蘑菇、水区贝壳的元素保持原产区归属。AI不参与数值和属性计算。现有背包材料保留原始元素、点数、名称与描述，不追溯重算。旧 MaterialPipValue 配置已退役，必须随同合并新JSON和插件Build.cs的NonUFS分发；缺失/错误规则会停用新采集并提示配置未就绪，不能偷偷退回3点。

本批不启用旧每日蘑菇的稀缺率、不启用评分惩罚或元素修正，不调整三日委托、合成运算、任务流程和区块保底。旧蘑菇流程保留；新产区不重复走旧背包增量转换。

## 名称、描述与背包

采摘先保存本地魔法物品，再通过现有共享DeepSeek接口的JSON模式命名。提示只给元素与材料分量，避免原蘑菇/贝壳形状主导结果；强调分量不等于已合成药剂档位，描述不新增游戏能力。

只接受name和description两个字符串：名称4–12字且至少4个汉字，描述25–65字；拒绝数字、换行/标记及明确属性机制词。格式错误最多修正一次，共享45秒与两次调用预算；网络失败或仍不合格保留本地记述。词面校验不是对全部创意与语义的保证。

结果仅改名称/描述及生成状态。库存键、实例ID、元素、点数、来源日和数量保持不变；已消耗物品不重建。文本保存失败恢复旧元数据，重载可沿原待生成标记重试。结果刷新采集提示、背包详情、尚未提交的合成选择和寻人界面；不重开已关闭的提示，不覆盖新采集物的弹窗。背包悬停使用显示名，数量已归零的条目不会继续留在详情选择。
