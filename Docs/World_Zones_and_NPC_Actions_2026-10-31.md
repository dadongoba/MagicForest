# 区块与NPC动作调查 / 分区草案 · 2026-10-31

## 现在实际具备什么

当前默认地图是 Dreamscape DemoMap，包含 Dreamscape_Gameplay 常驻玩法子关卡与 Witch_House 小屋实例。它们是内容组织单位，不能直接当成独立生态区块，否则整组开关可能同时影响 NPC、道路和资源。

运行时有三个以符文石为中心的元素产区：火40米、风40米、水60米。火/风每区默认最多36个蘑菇，水区最多24个漂浮贝壳；位置合格与否决定实际数量。产区内部只有独立资源ID，没有地理小区块ID，也没有统一的区块状态控制器。

地图二进制中确认有水域标记 ForestSwimWater / ForestSwimSurface 和玩法子关卡引用。贝壳代码引用 Corals2 下三个 Shells_Shell 模型，要求真实水面、水深≥1.8米、四周3米仍有水，玩家游泳且靠近才能采集，次日再生。修复批次02之后，这条采集会走魔法小物命名和描述，不再只发固定名称贝壳。本机三个完整/检查工程均未找到这些Corals2模型，增量仓库也没有收录；本次只能核对代码、地图标记与历史记录，不能确认运行实例的实际贝壳数。

## 建议划分，尚未修改地图

采用“小屋及回程保护区 + 每个产区三片功能区”的草案，约10块。每个产区：入口/保底通路一块，可变化采集地A、B各一块。水产区对应上岸点/回程保底通路与两片可游泳采集水面。保底通路应关联可获取的最低资源量，不能只是空走廊；具体最低量还需数值设计。

边界以实际坡坎、水岸、道路岔口和连通地块划定，避免平铺网格；每块需有明确的入口和稳定ID。资源点根据位置归属一个区块，跨界NPC按当前位置与活动计划关联。现有保存小地图内嵌缩略图只有256×256，能看中央水体与水道轮廓，不能据此假称已核实所有通路和精确多边形。

同一块的状态记录可关联：蘑菇/贝壳数量与活性、植物与局部环境表现、局部路线、NPC驻留或移动、交互动作预设。控制粒度是这些区块，不能直接封掉整个元素产区。小屋与回程、各元素最低可用资源必须有保护规则。

`Docs/World_Zone_Control_Draft_2026-10-31.json` 是可扩展的**设计草案**：区块多边形、阈值、资源倍率、最低量、NPC/地图状态预设均未填；所有规则禁用。它没有被游戏加载，不是已完成的运行时状态控制。确认边界后，仍需实现区块归属、表读取、结果匹配、状态保存与次日应用，以及环境/NPC具体绑定。

## 左侧评分数据与原有占位

`FForestBrewRecord.Result` 已保存 Target、Actual、Projection、PerpendicularCost、Cosine、DoseRatio、SumAbsolute、VerdictCode，配合 ReceiptId / Day 可作为前一天的权威输入。条件应取这些数值，而不是反向解析AI叙述。规则表命中后先确定次日真实状态，再让叙述描述该状态，避免文案宣称与游戏变化不一致。

插件已有 FDailyElementModifierRow 与 GetElementModifiersForDay / AddElementModifier，用于元素阻断、数量比例/上限与数值修正的预留。**当前新产区仍未读取这些效果，合成评分也未自动生成效果行。**本次按用户继续讨论分区的要求保留为待实施，不编造阈值或直接执行整产区关闭。NPC和地图状态控制同样未实际实现。

## NPC动作调查

本机 KindWitch / Natta / Fawnia 能确认的候选动画主要是站立、走、跑、跳/落地；KindWitch另有 Test_BlendShapes。资产名称与类型只证明候选资源存在，不证明所有动作可以直接跨骨骼通用。没有确认到三人可直接使用的挥手、接物、敲打、情绪动作集。

目前道路AI已有巡游、走向玩家、停止交谈、转身朝向玩家、结束后恢复活动。没有发现按每句AI回复自动调用表情/手势的桥接。新增展示功能提供 OnItemPresented(Npc,ItemKey) 事件，事件在反馈请求被接受后触发，可供后续核实过的动画绑定；**本次未绑定新的NPC动作动画，也未声称已有大量未调用的兼容动作。**
