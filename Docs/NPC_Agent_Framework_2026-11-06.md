# NPC知识隔离与分主题披露框架

## 本批实际范围

根据用户本轮明确选择“框架继续，委托文案先不接”，本批安装数值边界、主题计划、已披露状态和结算揭示入口；不修改原九份委托的目标、用途、槽位、指定材料、额度、评分或每日流程。新的正值/末日三元素方案只在待审文档中，尚未变成游戏任务。

`Config/ForestCommissionKnowledge.json` 当前为 `{ "version": 1, "entries": [] }`。这不是九份详细知识已经接好的标记；空注册表明确阻止草稿安装。已实现的框架在获准配置后才会提供新线索。在当前空配置下，NPC只能承接原用途，不会获得新九份底稿；旧用途中的“三样”仅在给台词模型的视图中替换为“这些”，避免暴露数量，原数据不改。

待审正文：[九份agent内部叙事底稿](Commission_Agent_Knowledge_Review_2026-11-06.md)。该稿采用完整起因、目标、内部数值依据、按提问使用的条目与结算揭示，不是玩家直接阅读的对话台词。

## 实际对话链路

1. `BuildPersonaSystemPrompt` 不再注入 `ElementRequest` 或委托编号。`Target`、额度、材料参考解法、完整审核稿、结算全文均不发送给说话模型。人设熟悉度仍由程序管理。
2. 既有语义接取判定增加最多两个主题的计划结果，只允许 `purpose/fire/wind/water/bounds/process`。不依赖对话次数。已接任务仅在有已审知识时继续规划；展示物品可问性质但不能写入接取。
3. 配置未来获准后，程序核对人物、委托ID、目标三值、审核标识、正向1—10范围、总量上限、用途和条目安全性；不匹配、重复或缺失就不启用。当前为空，不会从待审Markdown自动读取。
4. 当前追问的已审条目和此前开放的主题进入台词上下文；当前尚未开放的主题不发送。元素特征直接读取玩家图鉴的同一 `ForestElementCodex.json` 中的description，不重新让模型编定义。缺页或不支持的强度不会夹到最近档位冒充已知。
5. 主场景入口与插件 `RequestNpcDialogue` 入口均有回复关卡。先清理表演说明，再拦截常见数字写法：阿拉伯/全角、中文/财务数词、英文数词、罗马/圈号/上标等。玩家猜数时另拦截常见确认与否认说法。第一次不合格只重写台词，不重复执行接取；再次失败使用角色已有的安全兜底。网络错误仍是错误，不伪装成功。
6. 只有校验后的回复进入显示与正式历史。重写草稿不进历史、不进总结。新修订首次生效会从当前短期台词中移除不安全旧回复，并保留人物熟悉度、原始归档、任务与长期账本。
7. 旧记忆按叶子字段筛选，保留不相关的安全事实与不确定性标签；数字或旧绑定不会从摘要重新进入说话模型。原始存档不做破坏性删除。说话上下文不依靠数字元数据建立世界事实。
8. `KnowledgeDay/KnowledgeCommission/DisclosedTopics` 跟随角色存档。换任务只清披露主题，不清人设熟悉度。异步响应沿用人物、代次与日期校验；已经过时的结果不能登记或显示。
9. 结算UI增加独立揭示入口，只在有待确认的合成结果时读取。新目标和旧收据不匹配则不显示新底稿，避免错误解释旧结算。当前空配置不会添加任何新正文。

插件的共享网络传输没有更换地址、模型或密钥。只在NPC专用入口增加包装，采摘命名、寻人叙事、世界后果等通用请求不经过数字禁令。插件独立入口仍由调用者负责会话状态；主场景才负责主题规划与持久化。

## 后续获准配置的形状

每条entry包含：

| 字段 | 作用与可见范围 |
| --- | --- |
| commission_id、persona、target | 本地核对实际委托，不发送给说话模型 |
| approved、review_id | 人工批准及版本，草稿不得自行设置为已批准 |
| purpose | 已审的初始用途，不含数值，不含未解锁秘密 |
| topics | 六类线索文本，供程序按本轮提问选择；必须自然、清晰、无编号/数值 |
| private_brief（可选） | 完整内部叙事及数值理由，只供策划核对；对话构建器不读取 |
| settlement_reveal（可选） | 结算时完整揭示；可含数值，绝不复用为对话提示 |

用户审核的是叙事底稿，不是JSON。审核后再把底稿的可披露条目放入配置，并单独同步实际任务目标、可解性与结果页。人物往事仍由人设层级约束，不能靠任务知识绕过。

- 本批完整Air工程Mac UE5.8 arm64源码编译链接通过；修复编译问题后的构建6.64秒，最终构建6.22秒。
- 现有30条图鉴description逐条通过生产台词安全函数，避免拦截“一层”“一提”等正常描述；生产文本/主题函数的便携C++测试覆盖常见泄数形式、玩家猜数的确认/否认、人物三本书等正常陈述、未知主题与每轮最多两类主题。静态检查空批准表、两个NPC请求入口、提示词不含目标字段、旧异步校验仍存在。
- 原人物工厂、层级/别名/回复清理测试通过；原接取证据12组检查通过。原九份委托构建函数与基线逐字对照，保持不变。
- 没有打开/重启UE，没有运行PIE或调用在线模型，未验证Windows与打包运行。JSON加载分支和真实存档迁移目前有源码编译/路径检查，尚未做UE运行验证。
- 文本关卡是保守的表达校验，不是对所有隐喻、编码、语义确认的数学证明。合法的数量或含数词习语可能被重写，未来仍需真实模型对话回归。熟悉度数字是内部状态，不是目标配方；角色核心书籍数量可以正常表达。
- `DisclosedTopics`表示已经允许并成功返回的主题，不保证模型逐句讲完。语义计划仍依赖模型判断；无效计划回到用途，不能据此开放全部主题。
- 未批准九份文案，意味着完整的数值推断体验仍未完成；旧负数、风20/火11等问题本批不改，也不声称与图鉴已全部统一。
