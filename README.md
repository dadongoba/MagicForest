# demo3_UE58 增量更新仓库

本仓库用于保存 **Unreal Engine 5.8 项目 `demo3_UE58` 的更新与迭代文件**。由于完整工程体积较大，这里仅维护选定的新增、修改文件及相关说明，不上传完整工程。

GitHub 仓库：[daddongoba/MagicForest](https://github.com/daddongoba/MagicForest)。仓库公开，任何人都可以查看和下载更新文件。

**本仓库不是独立可运行的 UE 工程，也不是完整项目下载包。** 使用者需要自行准备匹配的完整工程，再按工程相对路径应用更新。因此，没有项目本体的人无法只凭本仓库打开或运行游戏；公开仓库用于分享迭代文件、变更说明和更新历史。

## 适用工程与目录

- 当前首批更新基于 `demo3_UE58` **1.5 版工程**，更新范围为 2026-10-05 至 2026-10-06。
- 引擎为 UE 5.8；历史开发记录标注的具体版本为 **5.8.3**，历史验证平台为 macOS（Apple 芯片）。这些是原记录信息，本目录未重新进行编辑器或运行验证。
- 完整工程的获取地址目前未提供。仅引擎版本相同并不能保证资产兼容，应用前还需确认工程版本与资产依赖一致。

|---|---|
| `Content/` | 本次纳入的蓝图等二进制资产，保留工程相对路径 |

| `Source/` | 首批模块参考文件，以及批次 2026-10-07-01 的 NPC 原生功能源码 |

## 让 AI 按项目进度协作

在 AI 使用的工作目录中保留本仓库的 `AGENTS.md`，并在任务提示里明确要求 AI 按其中的流程执行。约定要求 AI **先检查并同步 Git 与近期更新，再开始制作；制作后核对差异、更新 `CHANGELOG.md`、提交并推送**。若完整 UE 工程使用另一个 Git 仓库，开发工作应在完整工程中进行，完成后再把本次需要分享的变更按相对路径同步到本增量仓库。

可直接把下面这段发给 AI：

> 请先阅读仓库根目录的 `AGENTS.md`、`README.md` 和 `CHANGELOG.md`。严格按 `AGENTS.md` 规定的“同步 Git 并检查进度 → 制作和验证 → 同步增量文件、更新记录、提交并推送”顺序完成任务。开始修改前告诉我分支、工作区状态和最近相关进度；不要覆盖未知的本地改动或强制推送。完成后报告变更路径、验证结果、提交号和更新记录批次。

## 如何应用更新

1. 阅读 [更新记录](CHANGELOG.md)，确认需要的完整工程版本、前置更新、文件范围和已知问题。多批更新按记录中的顺序应用。
2. 关闭 UE 编辑器，备份完整工程或提交当前工程状态。
3. 将所需 `Content/` 文件按同名相对路径复制到完整工程。`.uasset` 是二进制资产，覆盖会替换原文件；若本地已有修改，应先保留副本并在编辑器内核对。
4. 对照配置变更合并 `Config/`。尤其是 `DefaultEngine.ini`，不要未经审查整文件覆盖，以免替换自己的渲染、平台或其他项目设置。`Source/` 仅在该批记录要求时应用。**涉及 `Plugins/` 时还需合并 `demo3_UE58.uproject` 的插件启用项**——该文件同样不要整文件覆盖。
5. 若更新涉及删除、重命名或迁移，按该批记录执行。**仓库中没有某个文件，不代表应从完整工程删除它。**
6. 打开完整工程，检查资产引用、蓝图编译、启动关卡及功能。涉及源码时重新生成项目文件并编译；涉及导航时按更新说明构建导航。

首批备份没有包含 `Content/Biomes/PNB_Enchanted_Forest/Map/Demo_Day.umap`。**批次 2026-10-07-01 已将该关卡纳入 Git LFS**，包含当前 NPC 摆放、道路和碰撞修改；仍需匹配完整工程的原有资源。克隆后运行 `git lfs install` 和 `git lfs pull`，避免把 LFS 文本指针作为地图使用。应用步骤见 [NPC 更新应用说明](Docs/NPC更新应用说明_2026-10-07.md)。

## 每次更新与上传的记录要求

**每次新增或修改更新文件，在提交与上传前必须同步更新 `CHANGELOG.md`，并将文件与文档放在同一次提交中。** 只更新文档或修正配置也需要记录。

每条记录至少写明：

- 更新日期与唯一批次编号（同一天多次更新可用 `2026-10-06-02` 等后缀）。
- 更新目的与具体行为变化。
- 新增、修改、删除、重命名文件的工程相对路径。
- 适用完整工程版本、前置更新与未包含的依赖。
- 应用步骤，特别是配置合并、关卡补充操作和删除操作。
- 实际验证方式、结果、未验证项和已知问题。
- 上传状态；未确认推送成功时标为“待上传”，成功后在后续记录维护中补充批次所对应的提交或标签（如有）。

记录按最新在前排列；复杂更新在 `Docs/` 编写详细说明并从更新记录链接。已发布记录若有错误，保留原意并注明更正，避免覆盖历史结论。仓库保存的是迭代文件的当前版本，历史版本由 Git 提交保存，无需每次复制一套完整备份目录。
